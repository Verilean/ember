# timer/ — retransmission, back-off, TIME-WAIT, idle close

| Fixture | Provenance |
|---|---|
| `linux-server-close.trace` | `tcp-scenarios.py server-close` against `ember-host`: Linux sends a line, waits; Ember closes the idle connection after `idleTicks` ticks (FIN-WAIT-1 → TIME-WAIT → LISTEN), Linux sees EOF. Ticks are `ember-host`'s 500 ms wall-clock ticks as recorded. |
| `retransmit-regenerate.trace` | M1.8: the echo is lost; after `rtoInit` ticks the same bytes are sent again (regenerated by the application, uIP model). |
| `backoff.trace` | M1.9: the gaps between retransmissions equal the table `rto k = min(48, 3·2^k)`, then RST and `drop reason=give-up`. |
| `syn-ack-giveup.trace`, `ticks-in-listen.trace` | hand-written. |
| `midframe-tick-deferred.trace`, `midframe-tick-stale.trace`, `midframe-tick-stray-byte.trace` | hand-written, expectations from `ember-replay --write`: a tick in the middle of a SLIP frame.  The stack builds what a tick sends in the packet buffer that holds the frame being received, so the tick waits for the end of the frame (`Spec.tickArrives`); a second tick while one waits gives the frame up (the decoder skips the rest, `oversize-frame` at its end) and both ticks happen, so a stray byte cannot stop the timers.  Before this rule the stack destroyed the half-received frame (found while proving `tick_step`). |
